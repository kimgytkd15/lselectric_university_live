태그 히스토리안

로깅 관리가 필요한 주요 데이터를 목적에 따라 데이터 로깅 모델(수집모델) 로 생성하여 관리합니다. 런타임 시 이력 엔진이 이 수집모델에 기반하여 데이터를 수집하고 저장합니다.

하나의 태그 데이터를 복수 개의 수집모델에 할당할 수 있어 다양한 데이터 분석이 가능합니다.

  • 수집 데이터의 조회 — 트랜드, 보고서, 리스트 트랜드 등에서 조회 가능하며, 스크립트에서 조회 가능한 API를 제공합니다.
  • 자동 계산되는 통계/적산 데이터 — 별도의 스크립트나 애플리케이션 없이 통계 및 적산 데이터가 생성됩니다.
  • 오픈소스 데이터베이스 — 오픈소스 객체-관계형 데이터베이스인 PostgreSQL을 사용합니다.

:::caution 저장 시간 형식 태그 히스토리안에서 설정한 태그들의 저장 시간은 Database에 UTC 형식으로 저장됩니다. Database에 직접 접근하여 데이터를 조회할 때 참고하십시오. :::

수집모델 종류​

수집모델설명조회 가능 데이터
정주기일정한 주기마다 태그값을 수집아날로그(현재값), 디지털(현재상태)
통계값설정한 태그에 대한 통계 데이터를 주기마다 생성아날로그(현재값, 최솟값, 최소시간, 최댓값, 최대시간, 평균값, 분산값), 디지털(가동 횟수, 가동 시간, 변경 횟수)
적산값값이 누적되는 태그에 대한 적산 통계 데이터 생성아날로그(변화량, 현재값)
문자열일정한 주기마다 문자열 태그 값을 수집문자열(현재값)

정주기​

최소 수집주기는 1초로, 빠른 실시간성 데이터 로깅에 사용되며 주로 트랜드 및 보고서의 순시값 조회에 사용됩니다. 런타임 시 정시에 수집하여 저장합니다.

수집주기를 2초로 설정한 경우, 매 0, 2, 4초 등 정시에 로깅 데이터로 저장합니다.

단위선택 가능한 주기
초1, 2, 3, 4, 5, 6, 10, 12, 15, 20, 30
분1, 2, 3, 4, 5, 6, 10, 12, 15, 20, 30
시1, 2, 3, 4, 6, 8, 12
일1

통계값​

최소 수집주기는 1분으로, 각종 통계 데이터를 자동 연산하여 저장합니다. 일정 기간 동안의 데이터 현황 파악에 사용되며 주로 보고서나 트랜드의 통계현황 조회에 사용됩니다. 런타임 시 매분 수집·연산하여 저장합니다.

수집주기를 5분으로 설정했고 현재가 2분 20초인 경우, 2분 20초부터 3분 00초까지의 데이터를 내부적으로 먼저 연산·저장한 뒤 4분 00초, 5분 00초에 정시 갱신합니다. 정시 5분 이후에는 새로운 데이터를 쌓기 시작합니다.

  • 아날로그 — 현재값, 최솟값, 최소시간, 최댓값, 최대시간, 평균값
  • 디지털 — 가동(On) 횟수, 가동시간, 변화횟수
단위선택 가능한 주기
분1, 2, 3, 4, 5, 6, 10, 12, 15, 20, 30
시1, 2, 3, 4, 6, 8, 12
일1 ~ 31
월1 ~ 12

적산값​

전력량계, 유량계 등 적산 성질을 가지는 태그를 등록하여 일정 기간 동안의 변화량을 연산·저장합니다. 별도의 스크립트나 메모리 태그 없이 시간별·일별·월별 변화량(사용량)을 조회할 수 있습니다.

런타임 시 매분 수집·연산하며, 1시간·1일·1개월의 적산 데이터를 자동 생성합니다. 따라서 수집 모델 주기 사이 어느 시간에 조회하더라도 가장 최근의 적산값을 확인할 수 있습니다.

노트

적산값 수집모델은 아날로그 태그만 설정 가능하며, 수집 주기와 단위를 선택하지 않고 매분 수집합니다.

  • 아날로그 — 변화량, 현재값

문자열​

최소 수집주기는 1초이며, 런타임 시 정시에 수집·저장합니다. 선택 가능한 주기는 정주기와 동일합니다.

  • 문자열 — 현재값

수집 주기 및 단위는 수집 방법에 따라 입력 가능한 값이 다릅니다.

수집모델 추가​

  1. 수집모델 그룹을 클릭하여 수집모델 목록 페이지로 이동합니다.
  2. 서브 내비게이션 상단 또는 테이블 우측 상단의 수집모델 추가 버튼을 클릭합니다.
  3. 우측 패널에 설정 정보를 입력하고 확인을 클릭합니다.

정보 / 수정 / 삭제 방법은 다른 엔티티와 동일합니다.

수집태그 설정​

태그 페이지에서 생성한 태그를 수집모델에 등록합니다. 서브 내비게이션 또는 테이블의 모델명을 클릭하여 이동합니다.

  • 태그 등록 — 테이블 우측 상단의 태그 등록 버튼 → 모달에서 태그 선택 → 확인. 좌측 하단 스낵바에 성공·복제·무효 건수 표시
  • 태그 제거 — 테이블 행 더보기 메뉴 또는 다중 선택 후 테이블 좌측 상단의 제거 버튼

참고사항​

수집모델 유효기간​

수집되는 데이터의 유효기한은 [프로젝트 경로]/[프로젝트 명]/Config/ehTagHistorian.ini 의 MAINTAIN_SETTING 에서 설정합니다.

  • 설정값을 사용하지 않으려면 저장기간과 삭제기한을 0으로 설정합니다 (0은 사용 안 함).
  • 수집모델의 저장경로는 PostgreSQL 설치 시 설정한 datadir 경로이며, DataWorX 기본값은 C:\EdgeHub\DataWorX\bin\Historian\pgData 입니다.
설정 키수집타입수집모델 단위저장기간 단위
PERIODIC_SEC_MAINTAIN_PERIOD정주기초일
PERIODIC_MIN_MAINTAIN_PERIOD정주기분월
PERIODIC_HOUR_MAINTAIN_PERIOD정주기시월
PERIODIC_DAY_MAINTAIN_PERIOD정주기일연
STATISTICS_1MIN_MAINTAIN_PERIOD통계분월
STATISTICS_NMIN_MAINTAIN_PERIOD통계분월
STATISTICS_HOUR_MAINTAIN_PERIOD통계시월
STATISTICS_DAY_MAINTAIN_PERIOD통계일연
STATISTICS_MONTH_MAINTAIN_PERIOD통계월연
ACCUMULATE_MIN_MAINTAIN_PERIOD적산분월
ACCUMULATE_HOUR_MAINTAIN_PERIOD적산시월
ACCUMULATE_DAY_MAINTAIN_PERIOD적산일연
ACCUMULATE_MONTH_MAINTAIN_PERIOD적산월연
STRING_SEC_MAINTAIN_PERIOD문자열초일
STRING_MIN_MAINTAIN_PERIOD문자열분월
STRING_HOUR_MAINTAIN_PERIOD문자열시월
STRING_DAY_MAINTAIN_PERIOD문자열일연

PERIODIC_MIN_MAINTAIN_PERIOD를 12로 설정하면, 모든 분단위 수집모델은 현재 월 포함 직전 12개월치만 조회 가능합니다. 현재가 3월이라면 전년도 4월부터 3월까지의 데이터를 조회할 수 있습니다. 설정값을 초과한 데이터는 테이블 이름 뒤에 _날짜를 붙여 별도로 저장됩니다.

경고

저장기간을 사용하지 않거나 너무 크게 설정하면 태그 이력의 데이터 사이즈가 커져 원하는 성능이 나오지 않을 수 있습니다.

로깅레벨 설정​

태그이력엔진이 동작하는 동안 발생하는 로그는 [프로젝트 경로]/[프로젝트 명]/Config/ehTagHistorian.ini 에서 설정합니다.

설정 키설명
LOG_DETAILLEVEL1 프로젝트 관련 내용 / 2 1번 + 태그이력엔진 설정 / 3 2번 + 모듈 내부 단계별 상태
LOG_WHERE1 프로젝트 Log 경로에 로그파일 생성 / 2 1번 + 디버그뷰 / 3 2번 + 윈도우 이벤트뷰어
LOG_MAXSIZE로그파일 최대 크기. 숫자 뒤 k, m, g 접미사로 단위 지정 (예: 200m = 200MB). 접미사가 없으면 Byte
LOG_RETENTIONDAYS최대 로그 파일의 수. 설정된 날짜 수보다 오래된 로그부터 삭제
