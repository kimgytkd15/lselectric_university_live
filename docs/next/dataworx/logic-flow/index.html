로직플로우 (LogicFlow)

LogicFlow는 DataWorX의 구성요소 중 하나입니다. 다양한 노드(컴포넌트)를 흐름 관계로 구성하고 이벤트 기반 모델링을 통해 데이터 조회·가공·입력 기능을 빠르게 구현할 수 있으며, 작성된 애플리케이션은 런타임 중 편집과 배포가 가능합니다.

LogicFlow는 Node.js 런타임 환경에서 구동되며, HTML5 지원 브라우저에서 편집기를 사용할 수 있습니다.

:::info 사전 지식 LogicFlow(기반 플랫폼: Node-RED)를 엔지니어링하려면 JavaScript 문법 및 SQL 문법에 대한 기본 지식이 필요합니다. 추가 라이브러리나 커스텀 노드 사용 시에는 해당 라이브러리의 구조와 동작 원리에 대한 이해가 요구됩니다. :::

기능​

  • 다양한 기능의 기본 노드를 제공하며, 필요 시 노드를 추가로 설치할 수 있습니다.
  • DataWorX의 태그 인터페이스를 사용할 수 있습니다.
  • LogicFlow의 실시간 데이터를 외부 DB로 내보낼 수 있습니다.

편집기 구성​

화면 구성설명
헤더인스턴스 이름, 사용자 프로필 메뉴, 메인 메뉴
팔레트플로우 작성 시 사용 가능한 노드 목록. 작업영역으로 드래그하여 사용
작업 영역노드의 위치, 속성, 흐름 연결을 작성하는 탭 영역. 플로우 단위로 구성
사이드바선택한 노드나 작업 공간에 따른 추가 옵션과 정보 제공

헤더​

  • 배포 — 플로우 편집 후 배포하기 버튼을 누르면 변경 내용이 반영된 런타임 동작이 수행됩니다. 빨간색은 배치 변경 사항 보류 중, 회색은 변경 사항 없음을 의미합니다.
  • 메뉴 — 팔레트 관리 및 편집기 환경설정을 변경합니다.

팔레트​

좌측 사이드바로, 핵심 노드와 설치된 서드파티 노드를 포함한 모든 사용 가능한 노드를 포함합니다.

  • 검색창 — 팔레트 상단에서 노드 이름으로 빠르게 검색
  • 노드 카테고리 — 여러 범주로 나뉘며, 서드파티 노드를 설치하면 새 카테고리가 생성될 수 있습니다. 서브플로우는 "서브플로우"로 분류됩니다.
  • 카테고리 확장/축소 — 팔레트 하단의 위쪽 화살표는 모든 카테고리 접기, 아래 화살표는 기본값으로 확장

작업 영역​

  • 플로우 — 에디터 작업 공간 내 탭으로 표현되며, 노드를 연결하여 애플리케이션을 구축하는 작업 공간입니다.
  • 노드 — 흐름을 생성하는 기본 구성 요소로, 각각 고유한 기능 또는 특정 동작을 나타냅니다.
    • 하나의 입력 포트와 여러 개의 출력 포트를 가질 수 있으며, 데이터 흐름을 정의하는 선으로 연결됩니다.
    • 일부 노드는 좌·우에 버튼이 있습니다(예: Inject 노드는 왼쪽, Debug 노드는 오른쪽).
    • 일부 노드는 하단에 실행 상태 아이콘이 표시됩니다(예: MQTT/WebSocket 노드의 "연결됨" + 녹색 원).
    • 상태 표시: 빨간 삼각형 = 오류, 파란 원 = 미배포 변경 사항, 노란색 정보 아이콘 = lint 문제

작업영역에 노드 추가

  • 팔레트에서 작업 영역으로 드래그
  • 빠른 추가: Ctrl(또는 Command) + 작업 영역 클릭 → 대화상자에서 노드 검색/선택

사이드바​

패널설명
정보 패널모든 플로우, 노드, 서브플로우, 전역 구성 노드를 트리 구조로 표시. 항목 호버 시 트리거·활성화/비활성화·표시/숨기기·잠금/해제·찾기 옵션 제공
도움말 패널노드 패키지 제작자가 제공한 문서나 Readme 확인. Node-RED 변경 내역(Changelog)과 신규 기능 소개 포함
디버그 패널디버그 노드가 출력하는 메시지 표시. 날짜/시간, 노드 이름, 속성 이름, 데이터 타입, 값 포함
구성 노드 패널인스턴스에 추가된 모든 구성 노드(Config node) 목록. 적용 범위(Global/플로우/서브플로우)별로 분류. 더블 클릭 시 편집 창 열림
컨텍스트 데이터컨텍스트 변수를 범위(Scope)별로 표시. 날짜/시간, 저장소 유형(메모리/영구), 변수 이름, 값 포함

노드 카테고리​

LSE 노드​

DataWorX 연동을 위한 전용 노드입니다.

노드설명
tag value입력이 발생할 때마다 DataWorX의 태그값을 읽어 플로우로 가져옴. 태그 및 태그그룹 선택 가능하며 실시간 태그값이 msg.payload로 출력
event trigger태그 이벤트 발생 시 플로우를 트리거
db mapper태그 데이터를 관계형 DB 테이블·컬럼에 매핑
influxdb mapper태그 데이터를 InfluxDB로 매핑
mongodb mapper태그 데이터를 MongoDB로 매핑
mobile notify모바일 알림 전송
delete file파일 삭제
inject controlInject 노드 제어
global function전역 함수 정의

LSE API​

전달된 msg에 대해 JavaScript 코드를 수행하는 노드로, 스크립트 내에서 DataWorX 태그 인터페이스를 사용할 수 있습니다.

노드 속성:

  • 이름 — 플로우 편집 화면에 표시될 이름
  • 코드 — 런타임 시 수행할 JavaScript 코드
  • 출력수 — 노드의 출력 수. msg를 배열로 내보내면 각 요소가 개별 출력으로 전달됨

제공되는 함수 그룹:

  • 태그 함수 — getTagVal 등
  • 프로젝트 함수
  • 이력데이터 조회 함수
  • 실시간 알람 관련 함수
  • 전역 태그값 참조
  • 이벤트 로깅 함수

getTagVal 함수는 DataWorX의 실시간 태그값을 즉시 가져오며, 여러 형태로 호출할 수 있습니다.

// 태그 이름으로 호출
getTagVal("D10.BLUE_01.ENCODER_TEMP_AXIS_1", function (value) {
  msg.payload = value;
  node.send(msg);
});

// 태그 이름 배열로 호출
getTagVal(
  ["D10.BLUE_01.ENCODER_TEMP_AXIS_2", "D10.BLUE_01.ENCODER_TEMP_AXIS_3"],
  function (value) {
    msg.payload = value;
    node.send(msg);
  }
);

// 태그 그룹 이름으로 호출
getTagVal("D10.BLUE_01", function (value) {
  msg.payload = value;
  node.send(msg);
});

Common 노드​

inject · debug · complete · catch · status · link in · link out · comment

inject 노드는 수동 또는 일정 간격으로 메시지를 전송하여 플로우를 시작합니다. 페이로드에는 문자열, 현재 시각, JavaScript 객체 등을 지정할 수 있으며, 반복 설정으로 "지정한 시간간격", "지정한 시간간격·일시", "지정한 일시"를 선택할 수 있습니다.

Function 노드​

function · switch · change · range · template · delay · trigger · exec · filter

API Reference로 node, context, flow, global, RED, env 객체와 기타 모듈·함수가 제공됩니다.

Network 노드​

mqtt in · mqtt out · http in · http response · http request · websocket in · websocket out · tcp in · tcp out · tcp request · udp in · udp out

Sequence 노드​

노드설명
split메시지를 메시지열로 분할. 문자열/버퍼는 구분자로, 배열은 크기값으로, 오브젝트는 key/value 쌍으로 분할. msg.parts 프로퍼티로 원래 메시지와의 대응관계를 기억
join메시지열을 결합하여 하나의 메시지로 생성. 자동/수동 등 3개 모드 지원
sort메시지열 정렬
batch메시지를 배치 단위로 묶음

Parser 노드​

노드설명
csvCSV 문자열 ↔ JavaScript 오브젝트 쌍방향 변환. 열 이름, 나누는 문자(기본 콤마), 출력 payload 형식 설정
htmlHTML 파싱
jsonJSON ↔ 오브젝트 변환
xmlXML ↔ 오브젝트 변환
yamlYAML ↔ 오브젝트 변환

Storage 노드​

노드설명
write filemsg.payload를 파일로 내보냄. 파일에 추가 / 덮어쓰기 / 삭제 동작 선택. 인코딩 및 디렉토리 자동 생성 옵션 제공
read file파일 내용을 문자열 또는 바이너리 버퍼로 불러옴
watch파일·디렉토리 변경 감시
mysqlMySQL 연동

:::tip 파일명 지정 파일명은 절대 경로로 지정하는 것을 권장합니다. msg.filename 프로퍼티로도 지정할 수 있으나, 이 경우 동작마다 파일을 닫아 성능 저하를 초래할 수 있습니다. :::

실행 및 권한​

DataWorX에 통합되어 실행되며, 엔지니어링 도구를 통해 편집 기능을 사용합니다. 접근 제어를 통해 LOGICFLOW_VIEW와 LOGICFLOW_EDIT 권한을 제어할 수 있으며, 권한에 따라 LogicFlow 화면이 달라집니다.

다국어 설정​

브라우저의 언어 환경에 따라 자동으로 적용됩니다. 변경하려면 ☰(메뉴) → 설정 → 창 → 언어에서 선택한 후, 새로고침(F5)으로 화면을 갱신합니다.

추가 노드 설치​

메뉴 → 팔레트 관리 → 팔레트에서 추가 라이브러리 노드를 다운로드 및 설치할 수 있습니다. 기본 제공되는 라이브러리는 인터넷에 연결되지 않은 환경에서도 설치가 가능합니다.

주의

LogicFlow는 Node.js v24.15.0 버전에서 동작합니다. 라이브러리 노드 설치 시 Node.js 버전과의 호환성을 확인한 후 설치하십시오.

LogicFlow 화면이 정상적으로 나타나지 않을 경우 브라우저 새로고침(F5)으로 화면을 다시 표시할 수 있습니다.

로그 (LOG)​

로그 파일은 프로젝트 경로 내 \log 폴더에 LF_YYYYMMDD.log 형식으로 자동 생성되며, 소프트웨어의 동작 상태 및 오류 발생 내역을 기록합니다.

[프로젝트 폴더]\Config\ehLogicFlow.ini 파일에서 다음 옵션을 설정할 수 있습니다.

설정 키설명
BUNDLE_SIZE_MB로그 파일의 최대 크기(MB 단위)
BUNDLE_COMPRESS로그 파일 압축 여부 (false: 비활성화, true: 활성화)

포트 옵션화​

LogicFlow에서 사용하는 서비스 포트는 [프로젝트 폴더]\Config\ehLogicFlow.ini 에서 변경합니다.

설정 키설명
LF_PORTLogicFlow 서비스가 사용하는 포트
REGISTRY_PORTLogicFlow 로컬 패키지 레지스트리가 사용하는 포트
