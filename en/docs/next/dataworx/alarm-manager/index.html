Alarm Manager

Alarms are a critical part of DataWorX and any SCADA system. This document describes how DataWorX processes alarms and how alarm groups are configured.

info

In DataWorX an alarm can only be set when the tag type is Analog or Digital, and alarms are only processed when the tag value was collected successfully.

Analog Alarms​

Boundary Alarm​

The most commonly used alarm when the tag type is Analog.

  • Four boundary values are configured: HH, HI, LO, LL.
  • The value range is divided horizontally, so the corresponding alarm is triggered when the tag value enters a zone and cleared when it leaves.
  • Each boundary can have a deadband area. When an alarm deadband value is set, the deadband rule is applied based on the direction of change and the zone the value is in.

Variance Alarm​

  • Triggered when the tag's current value changes from its previous value by at least the variance value set in the tag properties.
  • Once triggered, it is cleared when subsequent changes fall below the configured variance value.
  • Use it when a tag value should not change significantly.
  • Variance alarms are not subject to the deadband rule.

Separation Alarm​

  • Triggered by the difference between the major and secondary separation of a tag value relative to a reference value.
  • Separation alarms follow the same deadband rules as boundary alarms.
  • Differences from boundary alarms:
    • Separation alarms have no upper and lower division.
    • The reference value can be an absolute value or a relative value (another tag's value).

Digital Alarms​

When the tag type is Digital, alarms are configured based on the previous and current value.

Alarm typeDescription
ONTriggered when the value is ON, cleared when it is OFF
OFFTriggered when the value is OFF, cleared when it is ON
ON → OFFTriggered when the value changes from ON to OFF and cleared at the same time
OFF → ONTriggered when the value changes from OFF to ON and cleared at the same time
ChangeTriggered when the value changes and cleared at the same time

Alarm Delay​

Alarm delay means that when a field value shows an anomaly, the alarm is not raised immediately. Instead, the value after the configured delay is compared with the value before the first trigger, and the alarm is raised from that.

Configuring alarm delay​

Two items must be set.

1. Set the delay time

Enter the delay time under Tag → Alarm settings. This value is set per tag and applies to all alarms for that tag.

2. Set the alarm delay flag

Open [project path]/[project name]/Config/ehDataProcess.ini and set:

DP_ALARMDELAY_FLAG=1

Start the DataWorX runtime to apply the alarm delay time.

warning

Setting an alarm delay time can put a significant load on the DataWorX runtime and should only be used when strictly necessary.

Alarm Group Management​

Alarm groups divide tags into logical sets so that bulk actions can be taken per management point. Raised alarms can be filtered by alarm group when querying, or handled in LogicFlow.

PropertyDescription
Alarm group nameRequired. The name of the alarm group
Alarm group descriptionDescription of the alarm group
LevelThe level of the alarm group (1–10). When a tag has no alarm level of its own, the alarm group's level is used

Add, info, edit and delete are performed through the sub navigation menu, the table row more menu, and the buttons at the top right of the table.

Alarm Tag Settings​

Register tags created on the Tag page into an alarm group. Navigate here by clicking the alarm group name in the sub navigation or the table.

  • Register tag — Register tag button at the top right of the table → select tags in the modal → Confirm
  • Remove tag — Table row more menu, or multi-select and use the remove button at the top left of the table
note

The tag list in the registration modal only shows tags that already have an alarm configured.
