LogicFlow

LogicFlow is one of the components of DataWorX. You compose flows from a wide range of nodes and use event-based modelling to implement data lookup, processing and input quickly. Applications built this way can be edited and deployed while the runtime is running.

LogicFlow runs on the Node.js runtime, and the editor works in any HTML5-capable browser.

:::info Prerequisites Engineering LogicFlow (built on Node-RED) requires a working knowledge of JavaScript and SQL. Using additional libraries or custom nodes also requires understanding the structure and behaviour of those libraries. :::

Functions​

  • Provides a wide range of built-in nodes, with the option to install more.
  • The DataWorX tag interface is available.
  • Real-time LogicFlow data can be exported to an external DB.

Editor Layout​

AreaDescription
HeaderInstance name, user profile menu and main menu
PaletteThe list of nodes available when building flows. Drag them into the workspace
WorkspaceTabbed area where node position, properties and flow connections are defined, organized per flow
SidebarAdditional context-specific options and information for the selected node or workspace

Header​

  • Deploy — After editing a flow, pressing Deploy applies the changes to the runtime. Red means deployment changes are pending; grey means there are no changes.
  • Menu — Manage the palette and change editor preferences.

Palette​

The left sidebar containing all available nodes, including core nodes and installed third-party nodes.

  • Search box — Find nodes quickly by name from the top of the palette
  • Node categories — The palette is split into categories; installing third-party nodes may create new ones. Subflows are grouped under "Subflows".
  • Expand/collapse categories — The up arrow at the bottom of the palette collapses all categories; the down arrow expands them back to the default.

Workspace​

  • Flow — Represented as a tab in the editor workspace, providing a new workspace where nodes are connected into an application.
  • Node — The basic building block of a flow, each representing a specific function or behaviour.
    • A node can have one input port and several output ports, connected by wires that define the data flow.
    • Some nodes have a button on the left or right (for example, the Inject node on the left and the Debug node on the right).
    • Some nodes display an execution status icon underneath (for example, MQTT and WebSocket nodes show "connected" with a green circle).
    • Status indicators: red triangle = error, blue circle = undeployed changes, yellow info icon = lint issue.

Adding nodes to the workspace

  • Drag from the palette into the workspace
  • Quick add: Ctrl (or Command) + click in the workspace → search or select a node in the dialog

Sidebar​

PanelDescription
Information panelShows all flows, nodes, subflows and global configuration nodes as a tree. Hovering an item offers trigger, enable/disable, show/hide, lock/unlock and find options
Help panelDocumentation or Readme provided by node package authors, plus the Node-RED changelog and welcome tour
Debug panelMessages output by debug nodes, including date/time, node name, property name, data type and value
Configuration nodes panelAll config nodes added to the instance, grouped by scope (Global / flow / subflow). Double-click to open the edit dialog
Context dataContext variables by scope, with date/time, storage type (memory or persistent), variable name and value

Node Categories​

LSE nodes​

Dedicated nodes for DataWorX integration.

NodeDescription
tag valueReads DataWorX tag values into the flow whenever input arrives. Tags and tag groups can be selected, and the real-time value is output as msg.payload
event triggerTriggers a flow when a tag event occurs
db mapperMaps tag data to relational DB tables and columns
influxdb mapperMaps tag data to InfluxDB
mongodb mapperMaps tag data to MongoDB
mobile notifySends mobile notifications
delete fileDeletes a file
inject controlControls Inject nodes
global functionDefines global functions

LSE API​

A node that runs JavaScript code against the incoming msg, with access to the DataWorX tag interface from within the script.

Node properties:

  • Name — The name shown in the flow editor
  • Code — The JavaScript code executed at runtime
  • Outputs — The number of node outputs. Sending msg as an array delivers each element to its own output

Function groups provided:

  • Tag functions — such as getTagVal
  • Project functions
  • History data query functions
  • Realtime alarm functions
  • Global tag value reference
  • Event logging functions

getTagVal fetches DataWorX real-time tag values immediately and can be called in several forms.

// By tag name
getTagVal("D10.BLUE_01.ENCODER_TEMP_AXIS_1", function (value) {
  msg.payload = value;
  node.send(msg);
});

// By array of tag names
getTagVal(
  ["D10.BLUE_01.ENCODER_TEMP_AXIS_2", "D10.BLUE_01.ENCODER_TEMP_AXIS_3"],
  function (value) {
    msg.payload = value;
    node.send(msg);
  }
);

// By tag group name
getTagVal("D10.BLUE_01", function (value) {
  msg.payload = value;
  node.send(msg);
});

Common nodes​

inject · debug · complete · catch · status · link in · link out · comment

The inject node starts a flow by sending a message manually or at a set interval. The payload can be a string, the current time, a JavaScript object and more, and the repeat setting offers "at a set interval", "at a set interval within a time range" and "at a specific time".

Function nodes​

function · switch · change · range · template · delay · trigger · exec · filter

The API reference covers the node, context, flow, global, RED and env objects, plus other modules and functions.

Network nodes​

mqtt in · mqtt out · http in · http response · http request · websocket in · websocket out · tcp in · tcp out · tcp request · udp in · udp out

Sequence nodes​

NodeDescription
splitSplits a message into a message sequence. Strings/buffers split on a delimiter, arrays by size, and objects into key/value pairs. The msg.parts property records the relationship to the original message
joinCombines a message sequence into a single message, with three modes including automatic
sortSorts a message sequence
batchGroups messages into batches

Parser nodes​

NodeDescription
csvTwo-way conversion between CSV strings and JavaScript objects. Configure column names, the separator (comma by default) and the output payload format
htmlHTML parsing
jsonJSON ↔ object conversion
xmlXML ↔ object conversion
yamlYAML ↔ object conversion

Storage nodes​

NodeDescription
write fileWrites msg.payload to a file. Choose append, overwrite or delete, with encoding and automatic directory creation options
read fileReads file contents as a string or a binary buffer
watchWatches files and directories for changes
mysqlMySQL integration

:::tip Specifying filenames Specifying the filename as an absolute path is recommended. The msg.filename property can also be used, but then the file is closed after every operation, which can degrade performance. :::

Execution and Permissions​

LogicFlow runs integrated into DataWorX, and editing is available through the engineering tool. Access Control governs the LOGICFLOW_VIEW and LOGICFLOW_EDIT permissions, and the LogicFlow screen differs according to those permissions.

Language Settings​

The language follows the browser environment automatically. To change it, go to ☰ (Menu) → Settings → View → Language, then refresh the screen with F5.

Installing Additional Nodes​

Additional library nodes can be downloaded and installed from Menu → Manage palette → Palette. The bundled libraries can be installed even without an internet connection.

caution

LogicFlow runs on Node.js v24.15.0. Check library node compatibility with this Node.js version before installing.

If the LogicFlow screen does not appear correctly, refresh the browser with F5.

Logging​

Log files are created automatically in the \log folder under the project path as LF_YYYYMMDD.log, recording software status and errors.

The following options can be set in [project folder]\Config\ehLogicFlow.ini.

KeyDescription
BUNDLE_SIZE_MBMaximum log file size in MB
BUNDLE_COMPRESSWhether log files are compressed (false: disabled, true: enabled)

Port Options​

The service ports used by LogicFlow are changed in [project folder]\Config\ehLogicFlow.ini.

KeyDescription
LF_PORTThe port used by the LogicFlow service
REGISTRY_PORTThe port used by the LogicFlow local package registry
