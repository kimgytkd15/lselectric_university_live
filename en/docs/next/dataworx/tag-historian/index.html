Tag Historian

Key data that needs logging is managed through historian models created for each purpose. At runtime the history engine collects and stores data based on these models.

A single tag can be assigned to multiple historian models, enabling varied data analysis.

  • Querying collected data — Available in trends, reports and list trends, with an API for querying from scripts.
  • Automatically calculated statistics and accumulation — Statistical and accumulated data are generated without any separate script or application.
  • Open source database — Uses PostgreSQL, an open-source object-relational database.

:::caution Stored time format Timestamps for tags configured in the Tag Historian are stored in the database in UTC. Keep this in mind when querying the database directly. :::

Historian Model Types​

Historian modelDescriptionData available
PeriodCollects tag values every periodAnalog (current value), Digital (current state)
StatisticsGenerates statistical data for the configured tag every cycleAnalog (current value, minimum value, minimum time, maximum value, maximum time, average value, variance), Digital (number of runs, uptime, number of changes)
AccumulationGenerates statistical data about accumulated values for tags that accumulateAnalog (amount of change, current value)
StringCollects string tag values every intervalString (current value)

Period​

The minimum collection interval is 1 second, used for fast real-time data logging and mainly for instantaneous value lookups in trends and reports. At runtime it collects and stores on time.

With a 2-second interval, logging data is saved at every 0, 2, 4 seconds and so on.

Statistics​

The minimum collection period is 1 minute, automatically calculating and storing various statistics. It is used to understand data over a period of time, mainly for statistical queries in reports and trends. At runtime it collects and computes every minute.

With a 5-minute interval, if it is currently 2 minutes 20 seconds, the data from 2:20 to 3:00 is computed and stored internally first, then computed internally at 4:00 and 5:00 and updated on time. After the 5-minute mark it starts accumulating new data.

  • Analog — Current value, minimum value, minimum time, maximum value, maximum time, average value
  • Digital — Number of runs, uptime, number of changes
UnitSelectable period
Minutes1, 2, 3, 4, 5, 6, 10, 12, 15, 20, 30
Hours1, 2, 3, 4, 6, 8, 12
Days1 – 31
Month1 – 12

Accumulation​

Register tags with accumulating characteristics such as watt-hour meters and flow meters to compute and store the amount of change over a period. Hourly, daily and monthly usage can be queried without a separate script or memory tag.

At runtime it collects and computes every minute, and automatically generates 1-hour, 1-day and 1-month accumulated data. As a result, the most recent accumulated value is available no matter when you query between model cycles.

note

Only analog tags can be set for the accumulation model, and it collects every minute without selecting a collection interval or unit.

  • Analog — Amount of change, current value

String​

The minimum collection interval is 1 second, and at runtime it collects and stores on time. The selectable periods are the same as for Period.

  • String — Current value

Adding a historian model​

  1. Click the historian model group to open the model list page.
  2. Click the Add model button at the top of the sub navigation or the top right of the table.
  3. Enter the settings in the right panel and click Confirm.

Info, edit and delete work the same way as for other entities.

Tag Settings​

Register tags created on the Tag page into a historian model. Navigate here by clicking the model name in the sub navigation or the table.

  • Register tag — Register tag button at the top right of the table → select tags in the modal → Confirm. A snackbar at the bottom left shows the success, duplicate and invalid counts
  • Remove tag — Table row more menu, or multi-select and use the remove button at the top left of the table

Notes​

Historian model retention​

The expiry of collected data is set in MAINTAIN_SETTING in [project path]/[project name]/Config/ehTagHistorian.ini.

  • To disable it, set the storage and deletion periods to 0 (0 means not used).
  • The storage path of the historian model is the datadir path set when installing PostgreSQL; DataWorX uses C:\EdgeHub\DataWorX\bin\Historian\pgData by default.

Setting PERIODIC_MIN_MAINTAIN_PERIOD to 12 means every minute-based historian model can only retrieve the last 12 months including the current month. If it is currently March, data from April of the previous year through March is available. Data beyond the configured value is stored separately with _date appended to the table name.

warning

Not using a retention period, or setting it too large, can make the tag history data size grow so much that performance suffers.

Logging level​

Logs generated while the Tag Historian engine runs are configured in [project path]/[project name]/Config/ehTagHistorian.ini.

KeyDescription
LOG_DETAILLEVEL1 project-related content / 2 1 + Tag Historian engine settings / 3 2 + step-by-step status inside the module
LOG_WHERE1 create a log file in the project Log path / 2 1 + DebugView / 3 2 + Windows Event Viewer
LOG_MAXSIZEMaximum log file size. Add k, m or g after the number for KB, MB, GB (e.g. 200m = 200 MB). Without a suffix the value is in bytes
LOG_RETENTIONDAYSMaximum number of log files. Logs older than the configured number of days are deleted oldest first
