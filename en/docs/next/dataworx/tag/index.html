Tag

Tags are the fundamental unit of the DataWorX system. Every feature DataWorX supports operates on registered tags.

  • Tags are divided into the I/O class, which receives signals from field equipment, and the Memory class, which is registered virtually for use by upper-level systems.
  • The property panel shows tag information at a glance and makes tag engineering straightforward.
  • Excel file import/export lets you register and manage large volumes of tag data quickly.

Tag View​

Change the view using the tabs in the sub navigation.

Physical View​

Shows tags according to how they are physically connected to devices, regardless of their names. It is divided by class into I/O and Memory.

  • I/O tags — Tags whose data is collected through communication with actual field devices
  • Memory tags — Tags other than I/O tags, created virtually to make use of data
    • Normal tags — Created directly by the user through engineering
    • Group tags — A logical structure for grouping tags hierarchically, working like folders in a file explorer

Logical View​

Shows tags grouped into a logical hierarchy. The tag name is split on . to build the tree.

For a tag named A.B.C, groups A and A.B are created, with the tag A.B.C beneath them.

tip

The Logical View lets you group plant lines, products or characteristics to manage tags easily.

Digital On/Off Labels​

Set when the tag type is Digital.

  • On Label — String displayed when the tag value is 1
  • Off Label — String displayed when the tag value is 0

Raw Data​

Properties for the tag value collected from the device. This supports a wider range than the tag data type.

  • Integer: INT8 / INT16 / INT32 / INT64 / UINT8 / UINT16 / UINT32 / UINT64
  • Real: FLOAT / DOUBLE
  • BCD: BCD8 (-79 to 79) / BCD16 (-7,999 to 7,999) / BCD32 / BCD64
  • Unsigned BCD: UBCD8 (0 to 99) / UBCD16 (0 to 9,999) / UBCD32 / UBCD64
  • Bit: BIT1 (0 to 1) / BIT2 (0 to 3) / BIT3 (0 to 7) / BIT4 (0 to 15)

Raw Data Min / Max are set alongside.

Transform​

Rules for converting raw data collected from the device into tag data.

Transform ruleDescription
NoneThe raw value is applied as the tag value with no conversion
Ratio-BiasSlope/intercept method. Tag value = (Ratio × Raw value) + Bias
RatioConverts by ratio using the min/max of the raw value and the tag value
Ratio/OffsetUses the min/max of the raw value and the tag value, then adds an offset
  • Ratio — The value to multiply the raw value by
  • Bias — The value added after multiplying by Ratio
  • Offset — The value added to the result of the ratio conversion

Alarm​

Available when the tag type is Analog or Digital.

PropertyDescription
Alarm EventRaises an event on alarm occurrence or recovery
Delay TimeDelay before the alarm is raised. The alarm waits this long and uses the value at that moment. 0 disables it
DeadbandAlarm dead zone, preventing unnecessary alarms when the value fluctuates near the setpoint. Analog only
Alarm LevelAlarm severity, 1 to 10
Alarm TypeAlarm rule according to the tag type
Occurrence Msg / Recovery MsgStrings shown when the alarm occurs and recovers
Custom MsgUser-defined strings 1 to 4

Analog alarm types

  • Boundary alarm — Set values in the order HH > HI > LO > LL. HH cannot exceed the tag data maximum, and LL must be greater than the tag data minimum.
  • Variance alarm — Raised when the value changes by at least the variance value. Only numbers ≥ 0 are allowed.
  • Separation alarm — Separation baseline (absolute/relative), reference value or reference tag, major separation value, secondary separation value (must be smaller than the major value).

Digital alarm types — OFF / ON / ON > OFF / OFF > ON / CHANGE

For full occurrence and recovery rules see Alarm Manager.

Operation​

Set when the tag class is Memory and the type is Analog or Digital.

  • Operation Interval — Default 0. With 0 the expression follows the dependency order of the related tags and runs event-driven; a positive value makes each tag run the expression periodically and independently.
  • Operation Expression — Numeric and logical expressions

Group Management​

Group tags into a logical hierarchy. Groups appear in the Logical View tab of the sub navigation, at the top of the tag list.

Add, info, edit and delete work the same way as for tags, via the sub navigation menu, the table row more menu, and the buttons at the top right of the table.

Additional Features​

Copy / Paste tags​

note

Tag copy and paste is available only in the Logical View.

  1. Select tags or group items in the tag list (multi-select is supported).
  2. Click the copy button at the top left of the table, or press Ctrl + C.
  3. Navigate to the destination, then click the paste button or press Ctrl + V. Click X to cancel.

Export / Import tags​

Use Excel (.xlsx) files for bulk tag work, from the more menu at the top right of the table.

  • Export — Saves the project's tags to an Excel file named tags_[date]_[time].
  • Import — Saves the data in the Excel file as tags. Tags with the same name are updated; others are added. Results are summarized as total / success / failure counts and can be downloaded as an Excel file.

Import LS PLC​

Imports an LS ELECTRIC PLC variable file (CSV) and registers it as tags. Use the CSV exported from XG5000 with Project → Save variable/description file.

:::warning Supported drivers Import LS PLC supports XGI/XGK series drivers only (XGIEnet, XGICnet, XGKEnet, XGKCnet). :::

  1. Select channel — Choose a channel that uses a supported driver.
  2. Select device — Choose a device belonging to that channel.
  3. Upload CSV file — Only variables whose Type is Tag are imported. Files containing Korean text are detected automatically (EUC-KR).
  4. Review and edit tags — The uploaded variables appear as a spreadsheet.
    • Columns: TagName, Type, Variable, Address, DataType, Property, Scope, Comment
    • Tag names are generated from the variable name, with . replaced by _ and , by -. If there is no variable name, the format Variable_[address] is used.
    • The tag type is mapped automatically from the data type (BIT/BOOL → digital, INT/WORD/DINT/REAL → analog).
    • Variables with a BIT/WORD data type are registered as two separate tags prefixed with BIT_ and WORD_.
  5. Import results — Same name means edit, otherwise add. Results can be saved to Excel.

I/O Tag Validator​

Checks whether the communication addresses and communication blocks of the I/O tags registered on a device are configured correctly. It inspects address format, usable area and bit type, plus the existence, range and enabled state of the containing block, so misconfigurations are caught before actual communication.

:::warning Supported drivers The I/O tag validator supports XGI/XGK series drivers only (XGIEnet, XGICnet, XGILoader, XGKEnet, XGKCnet, XGKLoader). :::

Run it from the more menu at the top right of the table via Validate Tags.

  1. Select devices — Devices with unsupported drivers are shown greyed out. Select individually or all at once, then click Start validation.
  2. Validation results — A summary of total / error / warning / normal counts is shown with the affected tags. The result table has Severity, Tag name, Message, Channel, Device and Address columns. The download button saves io_tag_validation_result_[date]_[time].xlsx.

Severity

SeverityDescription
ErrorA configuration error that prevents normal communication. Must be fixed
WarningCommunication is possible but needs checking (disabled device/block, exceeding the allowed range, etc.)
OKNo issues found (only tags with issues appear in the result table)

Error checks

  • The address contains leading or trailing whitespace
  • An XGI address does not start with %, or an XGK address starts with %
  • The address format cannot be parsed
  • An area unusable by the driver is used
  • The address is a bit address but the tag type is not Digital
  • No block can exist for that area, so no matching block is possible
  • There is no matching communication block, no block for that area, or the address is outside the block range

Warning checks

  • The tag belongs to a device that is disabled
  • Auto Block is configured on the device
  • The matching block is disabled
  • The address is outside the allowed range for the area

Devices that cannot be found, use an unsupported driver, or fail during validation are reported as errors at the device level rather than per tag.

Use the sheet to add or edit tag data. It works the same as the UI Components — Spreadsheet.
