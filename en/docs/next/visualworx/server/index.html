Server

VisualWorX Server provides the service that delivers VisualWorX project data and EdgeHub DataWorX data to the VisualWorX Runtime.

Starting the Server​

  1. Select VisualWorX Server from the Program menu to start it.
  2. Once running, an icon appears in the taskbar along with a start message.
note

When VisualWorX Server is run for the first time it starts in a stopped state. Right-click the icon to complete the service settings and license registration, then start the service.

Service Settings​

Right-click the taskbar tray icon and select Service Settings.

Server settings​

Line redundancyMakes VisualWorX redundant at the line level. Enabled only when Import DataWorX settings is unchecked
System redundancyMakes VisualWorX redundant at the system level. Enabled only when Import DataWorX settings is unchecked
Primary IPThe primary IP address
Secondary IPThe secondary IP address for line redundancy
Master IP1The IP address of the server acting as Master in system redundancy
Master IP2The secondary IP address of the Master server for line redundancy
Standby IP1The IP address of the server acting as Standby in system redundancy

Project settings​

PropertyDescription
Project fileSelects the project file to serve. The extension is *.lsvx
New projectCreates a VisualWorX project
note

If an older project is set here, it is migrated automatically at service start so it can be used with the new version.

Secure communication​

PropertyDescription

Other settings​

PropertyDescription

tip

To change the HTTP port or WebSocket port for communication or security reasons, edit VisualWorXServer.info.

Redundancy Settings​

Line redundancy​

Line redundancy adds a secondary IP so that both are served.

  • Checking line redundancy enables the primary and secondary IP fields.
  • Also checking system redundancy enables six fields: Master IP1/IP2 and Standby IP1/IP2.
  • Enter the IP addresses this server will serve in the primary and secondary IP fields.
  • Enter the primary and secondary IPs served by the Master and Standby sides in Master IP1/IP2 and Standby IP1/IP2.

Switching by client connection IP:

  • Connecting on the primary IP → switches to Master IP1 or Standby IP1 according to the system redundancy role
  • Connecting on the secondary IP → switches to Master IP2 or Standby IP2 according to the system redundancy role

Example

Master PC A serves 10.13.110.110 and 10.13.111.111; Standby PC B serves 10.13.112.112 and 10.13.113.113:

  • PC A — primary/secondary IP and Master IP1/IP2 = 10.13.110.110, 10.13.111.111; Standby IP1/IP2 = 10.13.112.112, 10.13.113.113
  • PC B — primary/secondary IP and Standby IP1/IP2 = 10.13.112.112, 10.13.113.113; Master IP1/IP2 = 10.13.110.110, 10.13.111.111

System redundancy​

System redundancy places a Master and Standby IP so that clients switch to the other side when one goes down.

Checking system redundancy enables the primary IP, Master IP1 and Standby IP1 fields.

Example

PC A (10.13.110.110) is Master and PC B (10.13.111.111) is Standby:

  • PC A primary IP → 10.13.110.110 / PC B primary IP → 10.13.111.111
  • On both PCs, Master IP1 = 10.13.110.110 and Standby IP1 = 10.13.111.111

:::warning IP rules

  • For the Master role: primary IP = Master IP1, secondary IP = Master IP2
  • For the Standby role: primary IP = Standby IP1, secondary IP = Standby IP2
  • The Master IP and Standby IP must differ from each other :::

Client redundancy​

Client redundancy switches the screen automatically when a client connects and system redundancy is configured.

  • When both Master and Standby PCs are active, connecting to the Standby PC switches to the Master PC screen.
  • If the Master PC shuts down while its screen is open, the screen switches automatically to the Standby PC.
  • When the Master PC recovers, the Standby PC screen switches back to the Master PC screen automatically.
note

Connecting with localhost or 127.0.0.1 is treated as engineering and does not switch screens.

To avoid automatic client switching when connecting to the Master or Standby PC, uncheck client auto-switching on the login screen before logging in. After logging in you can re-enable it from the toolbar in the runtime top menu.

Creating a Project​

Run Service Settings → Project settings → New project.

Enter the project name, type, path, author and description, then click Confirm. The author and description are optional.

:::info Default administrator account When a project is created the default administrator account is ID admin / PW 1234.

Project names can be up to 60 characters using Korean/English letters, numbers and _. The default administrator setting is required to log in to the Editor and Runtime, and can be changed in the Editor under Project settings → Users. :::

SSL Settings​

Creating a self-signed certificate​

  1. Install OpenSSL from Win32/Win64 OpenSSL.
  2. Run the installed file to open a command prompt.
  3. Create a certs folder in your user account. Files generated by OpenSSL are created under this folder.
  4. Enter the following commands in order.
openssl genrsa -out privKey.pem 1024
openssl req -new -key privKey.pem -out private-csr.pem
openssl x509 -req -days 730 -in private-csr.pem -signkey privKey.pem -out cert.pem
caution

Enter the PC's IP address or localhost for the Common Name.

Three files are created in the SSL path after the commands complete.

Configuring SSL secure communication​

  1. Run Service Settings → Secure communication → Manage certificates.
  2. Click Register in certificate management.
  3. Register cert.pem as the certificate file and privKey.pem as the private key file.
  4. Connect to https://(the configured address) to see the VisualWorX screen.

License​

Right-click the VisualWorX tray icon and select the License menu.

info

On first installation you can start the service with a Trial license that is free for 14 days. It allows unlimited concurrent clients and includes the redundancy and chart features for 14 days.

Starting the service without a registered license shows a notification and the service cannot start.

License information​

View the currently registered license information. Reload re-reads an updated license, and Details shows the breakdown per feature.

License issuance​

A license key is provided by e-mail when VisualWorX is purchased.

  • EID — The login ID for offline license registration
  • Product Key — The product number for online license registration

License types​

TypeDescription
OnlineWhen the PC running VisualWorX can reach the LSE license server, register the license received by e-mail
OfflineWhen it cannot, generate an offline key, obtain an activation key from the license registration site and register it (.v2cp, .v2c, .h2r, .r2h, .h2h)

Online license registration​

  1. Click Register license in the License menu.
  2. Enter the Product Key from the license e-mail into Product Key (pkId) and click Register.
  3. Confirm the registration on the license information screen.

Offline license registration​

  1. Click Download offline user key in the License menu to download VisualWorX_Information.c2v.
  2. From a PC with internet access, go to ls-electric.prod.sentinelcloud.com/customer.
  3. Log in with the EID or Product Key listed in the license file.
  4. Click Activate Offline and enter the e-mail address that should receive the activation file.
  5. Click Select File and upload the *.c2v file from step 1.
  6. Click Complete Activation to activate the offline license.
  7. An Activation was successful message appears; download the offline license file (*.v2cp). A compressed copy is also sent to the e-mail address you entered.
  8. Upload the downloaded *.v2cp file and click Register.
  9. Confirm the registration on the license information screen.

License Transfer​

Moves a license in use to another PC.

  • Executable path: [VisualWorX installation path]\ETC\LicenseRehostTool\LicenseRehostTool.exe
  • With the default installation: C:\EdgeHub\VisualWorX\ETC\LicenseRehostTool\LicenseRehostTool.exe
note

This transfer method applies from VisualWorX v5.0.0 onward. If you need to migrate or keep license keys from a version earlier than v5.0.0, contact LS ELECTRIC.

Two PCs are involved — the New PC and the Current PC. Run LicenseRehostTool.exe on both.

1. [New PC] Create the info file (.id)

  1. Run LicenseRehostTool.exe on the new PC.
  2. Go to the Step 1. Generate New PC Info (New PC) area.
  3. Click the ... button next to Save PC Info File (.id) and choose a save path.
  4. Click Create to generate the info file (.id) and copy it to the current PC.

2. [Current PC] Create the transfer file (.h2h)

  1. Run LicenseRehostTool.exe on the current PC.
  2. Go to the Step 2. Export License File (Current PC) area.
  3. Select the product license to transfer from the Select License to Transfer list.
  4. Click the ... button next to Import New PC Info File (.id) and load the .id file from step 1.
  5. Click the ... button next to Save Transfer File and choose a save path.
  6. Click Create to generate the transfer file (.h2h) and copy it back to the new PC.

3. [New PC] Activate the license

On the new PC, run the product application and register the .h2h file from step 2 in the license registration window to complete activation.

:::danger Essential precautions 1. Check for running product sessions — Before creating the .h2h file on the current PC, the product application must be completely closed. If a session remains after closing, open http://localhost:1947/_int_/sessions.html and click Disconnect in the Actions column for that product session.

2. Do not lose the transfer file (.h2h) — If the generated .h2h file is lost, it cannot be regenerated under any circumstances. The license then becomes unusable on both the current and the new PC. License loss caused by failing to back up in advance is not covered by free reissue or compensation. :::

Service Status​

Right-click the tray icon and select Service Status.

User account status management​

Opens a window showing user account status. A newly created user shows Initial for the password and Unlocked for the lock state. Changing the password changes it to Applied.

admin can select another user's row and right-click to lock the account.

:::note Lock state terms

  • Period lock — During login attempts, the failure count (CFG_AUTHERR_LIMIT) was reached and login is locked until the access block time (CFG_AUTHERR_ACCINTERVAL) passes
  • Account lock — admin locked the user account by right-clicking in the user account status window :::

Authentication rules are changed in the USER_CONFIGRULE table of Database\VX_CONFIG.db in the project path.

ColumnDefaultDescription
CFG_PWDRULE{"min":8,"max":15,"special":0,"upper":0,"number":0}Password creation rules. min/max length, special minimum special characters, upper minimum uppercase letters, number minimum digits
CFG_AUTHERR_LIMIT5The number of authentication failures that triggers a login interval
CFG_AUTHERR_ACCINTERVAL005MIThe interval before the next login is allowed after the failure limit is reached. Three digits plus a two-letter time unit (SS seconds / MI minutes / HH hours). A value of 0 means permanent
CFG_PWD_CHGINTERVAL006MMPassword change cycle. Time units HH hour / DD day / MM month / YY year
CFG_SESSNOUSE_EXPIRETIME006HHIdle time before the session is locked (logged out). Time units MI minute / HH hour / DD day

User event log​

ColumnDescription
Log timeThe time the user wrote the log. The time range can be adjusted with the query range
ProjectThe project the log was written in
Log typeInfo, Warn, Error

VisualWorX Settings (VisualWorXServer.info)​

Open [VisualWorX installation path]\Server\VisualWorXServer.info in a text editor to change the settings.

caution

After changing these settings you must shut down and restart VisualWorX Server.

General properties​

PropertyDescription
pkgVersionThe installed VisualWorX version
licServerThe LSE license server (needed when registering a license key)
useHistRealRTSMWhether to use real-time values (true) or history values (false) when loading Tag Historian Period and String history data
useSetTagLoggingWhether tag value control is logged

networkServiceConfig​

Properties related to the server settings.

PropertyDescription
httpServicePortThe port VisualWorX Server serves on
httpBackendPortThe port of the web server acting as the HTTP backend
websocketBackendPortThe port of the WebSocket server acting as the HTTP backend
proxyBundledFilesWhether static files are served from the backend web server rather than directly. Default false
waitForBindableIPWaits at service start until the configured endpoint is serviceable. checkIntervalSec is the check interval in seconds; maxAttempts is the maximum number of checks (exceeding it prevents the service from starting)

redundant​

Properties related to system redundancy.

PropertyDescription
SyncServer.bindIpThe IP address bound when this VisualWorX server acts as a TCP server
SyncServer.portThe port used when acting as a TCP server or connecting to a remote VisualWorX server. Must be identical on both Master and Standby
SyncServer.preSharedKeyA 32-byte hex string AES encryption key used to encrypt data between VisualWorX servers. Must be identical on both Master and Standby

editorEnv​

Properties related to Drawing (Controls) that limit how many controls can be placed on a page.

PropertyDescription
pageConfigSettings for VisualWorX Editor pages
embedObjectCountDefinition of embedded objects such as the alarm viewer and trend viewer
embedObjectTotalCountTotal limit on embedded objects
trendViewCount / dataViewCountLimit on trend viewer / data viewer controls
comboCount / editBoxCount / listBoxCountLimit on combo box / edit box / list box controls
radioButtonCount / checkBoxCount / treeCountLimit on radio button / checkbox / tree controls
dbChartCount / dbGridCountLimit on VX chart / VX grid controls
alarmViewCount / webViewCount / soundCountLimit on alarm viewer / WebView / sound controls
datePickerCount / timePickerCountLimit on date / time controls
trendview.channelCountLimit on trend viewer channels
dataview.channelCountLimit on data viewer channels
dbchart.channelCountLimit on VX chart channels
warning

Change the number after the colon (:) to configure; -1 means no limit. Raising these values too far can affect VisualWorX performance, so take care.
